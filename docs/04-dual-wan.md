# 双线路适配、使用与回退

## 1. 先确认用途和授权

两个账号须由你获得使用授权，且学校允许同时接入。第二根校园网线不能直接作为普通 LAN 接入私有 Wi‑Fi 网桥；必须先把该口改为隔离的路由接口。

本方案将**新 IPv4 公网连接**按 1:1 选择出口，然后用连接标记固定出口。多个设备／下载连接有机会同时利用两条线路；单连接不合并带宽，也不提供跨故障无缝续传。局域网、路由器管理及私有地址不参与分流，IPv6 不在本方案范围内。

## 2. RA80 已验证的接口映射

| 部件 | 当前适配定义 |
| --- | --- |
| 第一校园入口 | 外部 WAN：`switch1` 端口 4；Linux `eth0` |
| 第二校园入口 | 外部 LAN1：`switch1` 端口 3；VLAN 3 → `eth1.3` |
| LAN CPU 口 | 端口 6 |
| WAN CPU 口 | 端口 5 |
| 保留私有 LAN VLAN 1 | `1 2 6` |
| 原 WAN VLAN 2 | `4 5` |
| 第二入口 VLAN 3 | `3 6t` |
| 私有 LAN | `br-lan`、`192.168.31.0/24` |

这些值写在控制脚本中，属于**特定硬件和固件适配**。尤其不能根据别的设备的“CPU 口一般是 0”来替换。修改 LAN 子网时，也必须审查脚本中的地址范围、策略表与防火墙规则。

## 3. 从零适配的操作顺序

仓库没有通用的一键 VLAN 安装器。以下是实施顺序，具体 UCI 区段名必须根据自己的固件确认；不要直接运行历史现场命令或复制其他设备的匿名区段 ID。

1. **暂不连接第二根校园网线。** 先确保主 Wi‑Fi 能管理路由器，记录 VLAN／端口映射。
2. 将自己的网络、防火墙和认证配置备份到路由器私有目录（0700），文件设为 0600；记录正常 WAN 状态。
3. 把 LAN1 从 VLAN 1 移出，建立只有端口 3 的独立 VLAN 3，保持原 WAN VLAN 不变。
4. 在独立 VLAN 尚未连接 CPU 时，预置该接口的 INPUT／FORWARD／OUTPUT 隔离保护，避免产生暴露窗口。
5. 再把 VLAN 3 加入 CPU 端口 6 的 tagged 成员，建立 `eth1.3`，保持不属于 `br-lan`，关闭该接口 IPv6。
6. 对 netifd 将第二接口登记为 `proto=none`、`auto=0`，由独立 DHCP 客户端管理，避免两套客户端争用。
7. 准备下面的独立二进制、配置和控制脚本，验证隔离链完整且 SSH 主 Wi‑Fi 管理正常。
8. 最后才接第二根校园网线，启动一次正常认证，确认取得地址后再开启分流。

如果第二根校园网线已经插在仍属于 LAN 网桥的口里，先断开这根线再实施新的适配。此前特定设备上的“不拔线改造”采用分阶段隔离与回退保护，不应当推广为通用安装步骤。

## 4. 独立实例与文件

第二实例不直接启动第二份原路径相同的 MentoHUST；两份程序会争用配置、PID 和日志。仓库提供针对**特定 SHA-256 原程序**的本地路径修改工具：

```bash
python3 app/dualwan/prepare_independent_binary.py \
  /你自己合法取得的/mentohust \
  /新目录/mentohus2
```

只修改四处等长路径，不改变认证协议；输入不匹配时拒绝执行。不要删除校验以强行适配未知二进制。合法获取方式与第三方许可由原认证项目决定，仓库不提供下载镜像。

目标路由器须具备：

```text
/data/mentoglass-dualwan/          0700
  mentohus2                      独立二进制，0700
  mentohus2.conf                 个人配置，0600，Nic=eth1.3
  dualwan.sh                    控制脚本，0700
  dhcp-start.sh                 第二线路 DHCP，0700
  dhcp-event.sh                 地址／租约事件，0700
  firewall-hook.sh              专属防火墙恢复钩子，0700
```

配置中的 `DhcpScript` 应指向 `/data/mentoglass-dualwan/dhcp-start.sh`，其他认证参数沿用适合本校的配置。账号密码仅在自己的路由器输入，不写进仓库或命令历史；部署时可以由 App 的第二账号编辑功能更新已有配置。

专属防火墙须允许内网发起转发及已建立连接返回，允许必要 DHCP 回复，拒绝校园入口主动访问路由器／私有 LAN。控制脚本的 `prepare` 对已经隔离好的 VLAN 做检查；它不负责从普通 LAN 拓扑安全地完成全套改造。

## 5. 维护任务

已有适配确认无误后，在**保留所有原任务**的基础上添加且只保留一条：

```cron
* * * * * /data/mentoglass-dualwan/dualwan.sh maintain >/dev/null 2>&1 # MentoGlass dual WAN
```

按当前固件的 firewall include 机制调用 `firewall-hook.sh`，避免普通防火墙重载丢失组件专用链。不要直接覆盖完整 crontab 或关闭系统防火墙。任务读取本机进程、物理端口、DHCP 租约和路由；没有互联网探测，没有失败账号无限认证循环。

第二线路就绪后，新连接可分流；主线路真实物理口断开时，新连接改走第二线路。检查以原有每分钟任务为准，不是瞬时切换。学校上游停止转发但网口、进程和租约仍在时，该检查可能无法发现。

## 6. 在 App 操作

进入「双线路」，先读取第二线路地址／就绪状态，再开启「双线路分流」。修改第二账号后保存，按需点击一次第二线路重新认证。已有未标记连接仍保留主出口。

NSS 加速仅对已验证设备开放，需要组件存在验证标记。**不要自己创建验证标记来跳过验证**。验证必须确认两条连接标记路径都进入正确硬件出口；关闭硬件加速清理 ECM 缓存，但不主动重启认证。关闭分流则恢复原加速设置。

## 7. 回退

先在 App 关闭分流，需要停用第二账号时再停止第二线路。普通回退无需恢复全套网络配置。

若要把 LAN1 恢复为普通内网口，**先拔掉 LAN1 的校园网线**，再使用自己修改前的备份恢复拓扑。校园网线仍插着时，把旧 VLAN 1 恢复为包含 LAN1，会把校园网络接回私有 LAN。不要执行这一顺序。

App 没有一键恢复出厂网络的按钮，也不承诺恢复所有第三方固件。详细操作应对照自己的备份与实际端口状态进行。
