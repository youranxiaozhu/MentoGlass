# 故障排查

## 1. App 打不开

确认 Mac 是 Apple Silicon、系统版本符合要求、App 包完整。优先在本机从源码构建；对下载包核实来源与公证状态，按 [Apple 官方说明](https://support.apple.com/102445)处理个别 App 的系统提示。

原生 MentoGlass 不使用早期 Python 管理器的 `127.0.0.1:28823` 服务。如果该网页打不开，不说明原生 App 也需要启动网页服务器。

## 2. 路由器网页可打开，App SSH 失败

按顺序检查：

1. Mac 是否连接主 Wi‑Fi；访客 Wi‑Fi、手机热点或错误网段可能无权管理。
2. App 是否填写路由器实际 LAN 地址及 SSH 端口。
3. 输入的是路由器 SSH 密码，而不是校园网密码或 Wi‑Fi 密码。
4. 路由器是否已有 SSH 服务；网页能打开不等于 SSH 已开启。
5. 若报身份变化，先确认是否换设备、刷固件或恢复出厂；不要为消除错误而自动删掉主机记录或关闭校验。

旧钥匙串项目不可读时，App 仍应可打开；手动输入已有 SSH 密码，再按自己的意愿保存。项目不更改你的登录凭据。

## 3. 认证进程存在，但没网

进程存在仅代表本地程序在运行。读取最新日志判断认证失败、心跳错误或 DHCP 问题；查看 WAN 地址和物理口。学校上游故障、账号限速／限制和 DNS 故障也可能发生。

有 `udhcpc: option requires an argument: i` 时，检查 `DhcpScript` 是否是缺少接口参数的 `udhcpc -i`。按 [DHCP 前提说明](02-router-preparation.md)对照固件处理。这一修复不能证明所有偶发断线都源于同一个原因。

## 4. 第二线路未就绪或分流暂停

查看第二账号认证日志、独立地址、租约与实际 LAN1 物理口。第二账号没有地址时，不强行创建就绪标记或开启分流。确认 `eth1.3` 不属于 `br-lan`，VLAN 配置与设备映射一致。

若第二线路地址与第一线路相同，DHCP 事件脚本会拒绝安装；不要绕过重复地址检查。两个接口同网段需要独立策略路由与地址处理，不能直接添加第二条同权默认路由来替代。

## 5. 某些网站频繁要求登录

按连接分流可能让同一应用的不同连接经过不同公网出口；有些服务会校验出口 IP，可能重新验证会话。可以先在 App 关闭双线路分流，以单线路定位问题。此项目没有域名粘性策略或单连接隧道聚合功能。

## 6. 打开硬件加速后异常

先关闭「双线路硬件加速」，保留分流并回到软件路径，再观察正常使用。不要用高并发压测来验证校园入口。短时被动验证通过不等于所有协议与长期故障条件都已覆盖。

## 7. 网口只有 100Mbps

先分清外部物理口和内部 CPU 接口。内部 `eth0` 显示 1000Mbps，不代表外部 WAN 网线也协商为千兆。确认上游端口支持、网线与接头条件；在获准维护范围内换线／换口排查。

不要盲目强制 1000Mbps。自动协商与本端千兆能力通告存在时，上游能力或线缆仍可能让连接停在 100Mbps。改区域、开启 NSS 或修改账号无法改变物理链路上限。

## 8. 改区域后 Wi‑Fi 暂时不可见

先等待无线重载与必要 DFS 检测；不要反复重载。重新连上主 Wi‑Fi 后刷新应用结果。若无法恢复，可使用保留的普通私有 LAN 口访问路由器检查自己的备份；**不要插到已经改作校园入口的 LAN1**。

区域备份在 `/data/mentoglass-wireless`。恢复无线配置不会要求把校园入口重新接入内网，也不应当为恢复管理而关闭防火墙或身份验证。

## 9. 提交 Issue 前

说明型号／固件、App 版本、连接方式、操作顺序和错误文字。去掉账号、密码、`EncodePass`、SSH 公钥指纹、公网 IP、个人 MAC、SSID 及完整配置。日志清理会隐藏常见密码字段，但不能保证所有身份信息都被移除，分享前仍需检查。
